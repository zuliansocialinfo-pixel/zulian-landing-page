# ZULIAN REFERENCE-CLASS WEBSITE — IMPLEMENTATION-CRITICAL PRD LOCKS

Document ID: `ZA-WEB-PRD-RC-01`
Version: `1.0`
Status: `OWNER PRD IMPLEMENTATION EXTRACT`

> This repository document records the implementation-critical locks from the owner-provided PRD used for this branch. It is not presented as a replacement for the complete owner artifact.

## Product decision
Zulian Architettura Digitale is one coherent **Web Experience System**, not a collection of unrelated HTML pages. The supplied quality reference is a **quality/mechanics floor**, never a template to clone. Brand, layout, code and assets from the reference are not copied.

## Distinctive experience thesis
`ARCHITECTURE BECOMES INTERFACE`

Primary experience logic:
`IDENTITY → RESPONSIBILITY → STRUCTURE → DEPTH → FUNCTIONAL PROOF → METHOD → CREDENTIAL → HUMAN → ACTION`

Rhythm:
`IMPACT → QUIET → TRANSFORMATION → QUIET → PROOF → EXPLANATION → HUMANITY → ACTION`

## Commercial canonical lock
Public website products:
- `ESSENTIAL` — €1.100
- `BUSINESS` — €1.600
- `SIGNATURE` — €2.400

Legacy public labels `Premium`, `Enterprise`, `Crescita`, `Sistema` are not canonical.

Current product-depth lock:
- Essential: 4 functional pages, 3 languages, minimum 1 video.
- Business: 7 functional pages, 5 languages, minimum 3 videos.
- Signature: 10 functional pages, 7 languages, minimum 6 videos.
- Legal pages are outside the functional page count.

## Proof law
Never invent or synthesize as proof:
- client results;
- case studies represented as real when they are not;
- testimonials;
- certificates;
- performance/business metrics;
- revenue/outcome claims.

Proof priority:
1. real documented client work when available and permitted;
2. runnable demonstrations;
3. verified credentials;
4. process artifacts;
5. accountable human/business identity;
6. transparent method.

Every Lab item must be unmistakably a demo when it is not client work.

## Technology lock
Baseline:
`SEMANTIC HTML5 + CSS + MINIMAL MODULAR JAVASCRIPT + RESPONSIVE MEDIA + PROGRESSIVE ENHANCEMENT`

GSAP, Lenis, Canvas, WebGL, Three.js or equivalent enter only when a specific approved scene proves the simpler route insufficient. No global advanced runtime is authorized merely to make the site feel premium.

## Critical no-JS invariant
Navigation, identity, offer, proof, contact and legal/privacy access must remain readable without cinematic JavaScript.

## Page grammar lock
Internal routes must not become simplified leftovers after an excellent Home. Each primary route gets a composition appropriate to its job:
- Home: flagship trust/acquisition experience.
- Soluzioni: depth/comparison system.
- Metodo: dependency/gate experience.
- Lab: functional proof.
- Certifications: evidence archive.
- Marco: human/editorial trust.
- Qualità: measurable QA system.
- Modelli: input→architecture demonstration.
- Contatti: intentionally simple, low-friction action.
- Privacy/legal: readable, restrained, factual.

## Quality floor
No primary route may hide a weak dimension behind a strong visual effect. Evaluate together:
- design;
- usability;
- creativity;
- content;
- responsive behavior;
- accessibility;
- performance discipline;
- semantics/SEO;
- metadata/markup;
- motion/interaction;
- originality.

Genericity FAIL when replacing logo/text would make the experience plausible for many unrelated agencies.

## Accessibility and responsive lock
Target WCAG 2.2 AA. Mobile is a distinct composition, not a reduced desktop. Reduced motion replaces high-cost/spatial motion without removing content or function.

## Performance lock
Performance claims require measurement on a real preview/live origin. Target good Core Web Vitals thresholds are treated as measurement targets, not pre-declared passes.

## SEO / privacy lock
Every indexable route needs descriptive metadata, canonical, internal linking and sitemap consistency. Privacy/consent must match the actual analytics/advertising stack; no non-essential tracking is added implicitly.

## Execution grammar
No material handoff is complete without:
`TRIGGER → PRECONDITIONS/START STATE → OWNER/FILE → ACTION/TRANSITION → EXACT VALUES → END STATE → ERROR/FALLBACK/ROLLBACK → ACCEPTANCE → VERIFICATION`

## Release boundary
`main` is production and publishes through GitHub Pages. This implementation branch must not mutate `main` or publish implicitly. A real browser preview and human acceptance remain release gates.
